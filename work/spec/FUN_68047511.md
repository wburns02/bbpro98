# FUN_68047511 () params=23

**1) PURPOSE**
During a pitching change, decide whether to execute a double switch: choose the outgoing position player from three batting-order slots and a bench replacement qualified for his position, accept if a computed score beats a random roll, and output the incoming/outgoing player pair.

**2) INPUTS**
- `this` — team/game state (guess: one team's object):
  - `this+0x172A0`: int[9] batting order (slot → player index)
  - `this+0x172C4`: int[9] defensive alignment (position → player index)
  - `this+0x172E8`: int; must be −1 to proceed (guess: DH index, −1 = no DH / pitcher bats)
  - `this+0x17336`: int batting-slot anchor for the 3-slot scan (guess: current batter's slot)
  - `this+0x17346`, `this+0x1736A`: int[9] each, indexed by position (guess: counts of primary-position / qualified players available)
  - `this+0x0000`: int array indexed by player index 0–39 (guess: player IDs)
  - Player struct `i` at `this + i*0x93C + 0x140` (i = 0..39):
    - `+0x004`: sub-object used for position eligibility (`FUN_6803d9f9`) and identity/name (`FUN_6803da2b(...,0)`, `FUN_6803d745`)
    - `+0x29E`: status field; must be 0 (guess: "not currently in game")
    - `+0x7F0`: ratings object; `FUN_6803e287(ratings,pos)` or `FUN_6803e2e1(ratings,0x18)` return a rating (guess: defensive rating at position)
- `param_1` (char): rating mode. 0 → `FUN_6803e287(ratings, pos)`; nonzero → `FUN_6803e2e1(ratings, 0x18)` (guess: alternate/overall rating).
- `param_2`: incoming relief pitcher object (uses its `+4` sub-object).
- `param_3`, `param_4`: int* output slots.

**3) RULES**
1. Set `*param_3 = *param_4 = &DAT_681433d0` (null sentinel). If `*(this+0x172E8) != -1`, return (no double switch).
2. For k = 0..2, let slot `s = ((*(this+0x17336) + 9) − (k+1)) % 9`, i.e. anchor−1, anchor−2, anchor−3 (mod 9). Let P = battingOrder[s]. (Guess: the three most recent batters, or next three due up, depending on anchor semantics.)
3. Find P's position `p` by scanning alignment[0..8] for P. If P is not on the field, skip this slot.
4. Bench scan (re-run per slot): among players i = 0..39 with `FUN_6803dded(player+0x29E) == 0` and `FUN_6803d9f9(player+4, p) != 0`, select the one maximizing rating R (mode per `param_1`, at position `p`). Strict `>` comparison from a 0 start ⇒ rating must be > 0; ties go to lowest index.
5. Slot is eligible iff: candidate found; candidate re-qualified at `p` via `FUN_6803d9f9`; `*FUN_6803da2b(param_2+4, 0) != *(this + candidate*4)` (guess: incoming pitcher ≠ candidate, via ID table at this+0); and `p != 0` (guess: 0 = pitcher position).
6. Score = `PB[doubleSwitchBase]` (0)
   - `+ PB[doubleSwitchPitcherDueAdjust]` (25) if `FUN_680434e5(this) & 0xFF` (guess: pitcher due to bat)
   - `+ PB[doubleSwitchPHAdjust]` (25) if `FUN_68047c98(this, outgoing's field-0 value)` (guess: outgoing player is a pinch hitter)
   - `+ PB[doubleSwitchNoPrimaryPosAdjust]` (−10) if `*(this + p*4 + 0x17346) < 2`
   - `+ PB[doubleSwitchNoQualifiedPosAdjust]` (−25) if `*(this + p*4 + 0x1736A) < 2`
   - Current-def tier on outgoing player's rating at `p` (strict `<` comparisons; band VeryHigh is r ≥ 75, High 49 ≤ r < 75, Med 28 ≤ r < 49, Low 14 ≤ r < 28, VeryLow r < 14):
     - r ≥ `PB[doubleSwitchVeryHighCurrDefThresh]` (75) → `+ PB[doubleSwitchVeryHighCurrDefAdjust]` (−100)
     - elif r ≥ `PB[doubleSwitchHighCurrDefThresh]` (49) → `+ PB[doubleSwitchHighCurrDefAdjust]` (−50)
     - elif r ≥ `PB[doubleSwitchMedCurrDefThresh]` (28) → `+ PB[doubleSwitchMedCurrDefAdjust]` (0)
     - elif r ≥ `PB[doubleSwitchLowCurrDefThresh]` (14) → `+ PB[doubleSwitchLowCurrDefAdjust]` (20)
     - else → `+ PB[doubleSwitchVeryLowCurrDefAdjust]` (50)
   - New-def tier on candidate's rating at `p`, same thresholds (`doubleSwitchVeryHigh/High/Med/LowNewDefThresh` = 75/49/28/14):
     - ≥75 → `+ PB[doubleSwitchVeryHighNewDefAdjust]` (50); ≥49 → +20; ≥28 → 0; ≥14 → `−50`; else `PB[doubleSwitchVeryLowNewDefAdjust]` (−100)
7. Keep the best candidate: if score > best-so-far, remember (score, outgoing P, candidate).
8. After all 3 slots: execute iff outgoing and candidate were found AND best score > `FUN_68082999(&DAT_68185a60, 100)` (guess: uniform 0–99 RNG draw). Score is not clamped. Otherwise outputs stay sentinel.
9. On execute: `*param_3` = player object of candidate (incoming position sub), `*param_4` = player object of outgoing player, via `FUN_68041d33`. The actual lineup/position swap is not done here.

**4) OUTPUT / SIDE EFFECTS**

- One RNG draw whenever at least one valid candidate exists.
- If global `DAT_68114ba4` (log flag) ≠ 0 and `local_18 > 0` — note: `local_18` is the **last evaluated** candidate's score, not the best (`local_24`); quirk — writes a log: "=== Check For Sub ===", "Double Switch", "Relief Pitch: <new pitcher> going in", "Defensive Sub: <param_3> in for <param_4>", "Chance: <n>".
