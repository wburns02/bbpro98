# FUN_680537ad () params=16

DRAFT (GLM-Flash, unaudited)

1) PURPOSE
Computes a 0–100 percentage chance that the current batter attempts a sacrifice bunt, based on outs, batter quality, pitcher batting, runners, and close/late game state.

2) INPUTS
- `param_1` — game/context object.
  - `+0x6b` — handle/struct used for a rating lookup; compared against CH and PH thresholds (likely current batter's contact & power ratings; guess).
  - `+0x67` — second rating lookup, used only for the 1-out close/late check (possibly on-deck batter or other player; guess).
  - `+0x7b` — team index into team table (`&DAT_68114ba8`, stride 0x173be); a byte flag read from the team struct (likely "batter is a pitcher" / no-DH; guess).
- Globals at `0x68143ee0` via `FUN_68002c80` (bVar3; behaves as out count: 0/1/2) and `FUN_6800f1e0` (bVar4; gated `< 2`, possibly strikes; guess).
- `FUN_68032ff0(param_1)` — nonzero required for any chance (likely runner on 1st; guess).
- `FUN_6800f600(param_1)` — used for the "on 1&2" bonus (likely runner on 2nd; guess).
- `FUN_6800f640(param_1)` — nonzero disables the chance entirely (likely runner on 3rd; guess).
- `FUN_68039356(0x681147a0)` — boolean, gates the CL (close/late) adjustments (guess).

3) RULES
1. Precondition gate: out count < 2 AND bVar4 < 2 AND runner condition bVar1 (`FUN_68032ff0 != 0` AND `FUN_6800f640 == 0`). If any fails, chance = 0.
2. Batter quality gate: rating lookup on `+0x6b` must be ≤ PB[sacChanceMaxCH] (69) AND ≤ PB[sacChanceMaxPH] (39); otherwise chance = 0. (Same call site is reused for both thresholds — see UNCERTAIN.)
3. Base chance = PB[sacChanceBase] (10).
4. If team flag (`FUN_68049594` on team struct) is set: += PB[sacChancePitcherAdjust] (50).
5. If outs == 1: += PB[sacChance1OutAdjust] (−25).
6. If close/late flag (`FUN_68039356`) set: += PB[sacChanceCLAdjust] (30), then:
   6a. If `+0x6b` rating ≤ PB[sacChanceCLLowCHThresh] (40) AND ≤ PB[sacChanceCLLowPHThresh] (40): += PB[sacChanceCLLowCHPHAdjust] (−25).
   6b. If outs == 0 AND bVar2 (`FUN_68032ff0 != 0` AND `FUN_6800f600 != 0` AND `FUN_6800f640 == 0`, i.e. runners on 1st & 2nd, none on 3rd): += PB[sacChanceCL0OutOn12Adjust] (30).
   6c. If outs == 1 AND `+0x67` rating ≥ PB[sacChanceCL1OutODHighCHThresh] (59) AND ≥ PB[sacChanceCL1OutODHighPHThresh] (49): += PB[sacChanceCL1OutODHighAdjust] (10).
7. If team flag set AND `+0x6b` rating ≤ PB[sacChancePitcherLowCHThresh] (9) AND ≤ PB[sacChancePitcherLowPHThresh] (9): += PB[sacChancePitcherLowCHPHAdjust] (20). (Applies regardless of close/late flag.)
8. All comparisons are inclusive (`<=` for max/low thresholds, `>=` via `thresh <= value` for the high thresholds).

4) OUTPUT/SIDE EFFECTS
- Returns the accumulated short, clamped to [0,100] via `FUN_68014c70(value, 0, 100)`.
- No side effects observed (all sub-calls appear to be reads).

5) UNCERTAIN
- Identities of all getter functions (`FUN_68002c80`, `FUN_6800f1e0`, `FUN_68032ff0`, `FUN_6800f600`, `FUN_6800f640`, `FUN_68039356`, `FUN_68049594`) are inferred from param names and gating logic only.
- Meaning of `+0x6b` vs `+0x67` (which player each refers to; the "OD" in the 1-out param names suggests on-deck, unverified).
- The decompiler shows the identical call `IsTracking(*(param_1+0x6b))` for both CH and PH threshold checks; the real function almost certainly takes a second argument (rating selector) that was not recovered, so CH and PH are read as distinct values in the binary.
- Whether bVar4 is strikes or balls; only `< 2` gating is certain.
- Exact meaning of the team-struct byte flag (pitcher batting vs. league/DH flag).
- Whether `FUN_6800f640` is "runner on 3rd" or some other base-state predicate.
