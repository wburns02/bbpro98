# FUN_68003899 (void __thiscall FUN_68003899(void *this,short param_1))

DRAFT (GLM-Flash, unaudited)

**1) PURPOSE**
Computes a speed value for the object from an input rating plus PB-tuned base/percent terms, stores it at `this+0x32`, then derives a secondary value at `this+0x38` from it.

**2) INPUTS**
- `param_1` (short arg) — input rating fed to helper; guess: raw speed/movement rating.
- `this+0x34` (int, read) — second operand to the same helper used with `speedPct`; guess: a percentage/rate modifier.
- `PB[speedPct]` (default 5), `PB[speedBase]` (default 20).
- `this+0x32` (short, write-then-read) — working/final speed slot.

**3) RULES**
1. `adj = FUN_68005b80(param_1, PB[speedPct])` — helper semantics not defined here; the name `speedPct` suggests a percent computation on `param_1` (guess).
2. `this+0x32 = (short)adj + (short)PB[speedBase]` — 16-bit truncated add, stored as short.
3. `this+0x32 = (short)FUN_68005b50(1, this+0x32)` — helper takes literal `1` and the current speed; possibly a floor/clamp at 1 or a variance roll (guess).
4. `this+0x38 = FUN_68005b80((int)this+0x32, *(int*)(this+0x34))` — same helper as rule 1, applied to the final speed and field `0x34`; result stored as full 32-bit int (no short truncation).

**4) OUTPUT / SIDE EFFECTS**
- Writes short at `this+0x32` (final speed).
- Writes int at `this+0x38` (derived value).
- No PB writes; no other state touched. Single caller: `6803311a`.

**5) UNCERTAIN**
- Behavior of `FUN_68005b80` and `FUN_68005b50` — only their call signatures are known; all arithmetic beyond the rule-2 add is opaque.
- Meaning of `param_1`, field `0x34`, and field `0x38`; what the speed value represents physically (runner, pitch, ball, etc.).
- Whether rule 3 can alter the value (identity/clamp/random unknown).
- Behavior on 16-bit overflow in rule 2 if helper results exceed short range.


CORRECTIONS (audit pass 2, GLM-Flash vs decompile; findings verified shaped, apply when editing):
- 68003899 (rule 4, final `FUN_68005b80` call): draft formula passes `(int)this+0x32` — the *address* of the speed slot — as the first argument. The decompile passes the *value* loaded from that slot as a sign-extended short: `FUN_68005b80((int)*(short *)((int)this + 0x32),*(int *)((int)this + 0x34));`. The draft's own prose ("applied to the final speed") is correct, but the written call signature is wrong (missing deref, and the operand is a short read, not an int). All other claims check out: `FUN_68003170(0x2d7)` = PB[727] speedPct (default 5) feeding rule 1; `FUN_68003170(0x2d6)` = PB[726] speedBase (default 20) in the rule-2 short add; rule 3's `FUN_68005b50(1, *(short *)((int)this + 0x32))` with short write-back; int write to `this+0x38` with no truncation; single caller `6803311a`.
