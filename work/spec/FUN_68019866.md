# FUN_68019866 (FastSim_FGAME) params=50

DRAFT (GLM-Flash, unaudited)

## 1) PURPOSE
Loads defensive positioning data (infielder depth/angle for 4 alignments, outfielder depth/angle for 3 alignments) from the PB balance table into a global position table, converting units, and sets four fields of the caller's struct to 2.

## 2) INPUTS
- `param_1` — pointer to a caller struct; only offsets 0x15, 0x19, 0x1d, 0x21 are written (meaning unknown).
- PB table entries listed above (read-only). No other inputs.

## 3) RULES
1. Write `2` (as 32-bit values) to `param_1+0x15`, `+0x19`, `+0x1d`, `+0x21` (four consecutive stride-4 fields).
2. For every infielder parameter pair, write to the global table as a 16-bit pair (depth, angle):
   - depth: `(int16)PB[<align><Pos>Dist] * 30` (0x1e)
   - angle: `(int16)((PB[<align><Pos>Angle] << 13) / 45)` — i.e. degrees × 65536/360 ≈ 182.04 per degree (16-bit binary angle, 65536 = full circle); truncating division; negative angles stored two's-complement.
3. For every outfielder parameter pair, write:
   - depth: `(int16)PB[<align><Pos>Pct]` — stored raw, no scaling.
   - angle: same `<<13 / 45` conversion as above.
4. Table layout — base 0x680c8fc8, int16 slots (depth, angle), written in this order:
   - 0x680c8fc8 normal IF: 1B, 2B, 3B, SS (fc8/fca, fcc/fce, fd0/fd2, fd4/fd6)
   - 0x680c8fe0 normal OF: RF, CF, LF (fe0/fe2, fe4/fe6, fe8/fea)
   - 0x680c8fec guardLines IF: 1B, 2B, 3B, SS
   - 0x680c9004 guardLeft OF: RF, CF, LF
   - 0x680c9010 cutoffRun IF: 1B, 2B, 3B, SS
   - 0x680c9028 guardRight OF: RF, CF, LF
   - 0x680c9034 doublePlay IF: 1B, 2B, 3B, SS
5. Structural observation: the IF and OF blocks interleave at a regular 0x24-byte stride (records at 0xfc8, 0xfec, 0x9010, 0x9034), each record = 4 IF slots (16 B) + 8 unwritten bytes + 3 OF slots (12 B). Consistent with one array of 4 alignment records (9 fielder slots each, 2 slots per record unwritten — possibly P/C) or two parallel tables (IF: normal/guardLines/cutoffRun/doublePlay; OF: normal/guardLeft/guardRight).
6. Angle sign convention (inferred from defaults, not from code): 0 = straight away, positive = third-base/left side (3B +35, SS +17, LF +25), negative = first-base/right side (1B −35, 2B −12, RF −25).

## 4) OUTPUT / SIDE EFFECTS
- Populates global table at 0x680c8fc8–0x680c9043 with converted depth/angle values (16-bit stores; overflow wraps).
- Sets the four 32-bit fields in `*param_1` to 2.
- No return value.

## 5) UNCERTAIN
- Meaning of the four fields set to 2 in `param_1` (and what the struct is).
- Physical unit of the Dist values (defaults 90–155 suggest feet from home plate — guess) and what the ×30 scale produces.
- Semantics of the outfield "Pct" values (percent of what — fence distance? — not shown here).
- Whether the table is one 4-record alignment array or two parallel tables; identity of the 8 unwritten bytes per record.
- Whether the doublePlay record's OF slots (0x680c904c+) are initialized elsewhere.
- Angle sign convention is inferred from default values only.
