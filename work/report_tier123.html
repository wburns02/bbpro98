BBPro98 reverse engineering, Tiers 1 to 3

Verdict

Tier 1 is done: all 14 binaries are labeled and about 7,500 functions are renamed in Ghidra. Tier 2 is partial: the PYR format round-trips, the ASN container is framed but its fields are not decoded. Tier 3 is a start, not a spec: 74 function drafts exist and only about 5 are audited against the decompile. Tier 4 was not started, as instructed.

What was accomplished

  • Tier 1: every binary in the Ghidra project was labeled (deterministic pass, GLM-Flash batches, split-batch escalation, DeepSeek-Flash for the residue). Renames applied only for XREF_CONFIDENT and STRING_XREF labels, with MFC false matches filtered out.
  • Tier 3: the PlayBalance table (872 ints from PB.INI) is mapped for BBSIM and FastSim. Structural finding: init loaders copy PB values into globals, other functions read the PB getter at decision time. 74 function drafts and an index live in work/BBSIM_SPEC.md and work/spec/.
  • Audited rule: the batter look-type selection (FastSim FUN_6800cccc), a weighted random pick over 8 slots with a closed-form weight formula, recorded in the spec.
  • Tier 2: PYR round-trip tests pass 4 of 4. ASN record framing and table record counts verified. The ASN holds no plaintext, shifted or XORed team names, so names are probably joined by id from other files.

Loop stats

One Hive stream hang was killed and routed to the escalation path. Run recorded as tbl-20261007T044551Z-66b366 (started and finished late, so it records the run but not its true duration).

Landmines learned

  • Many CSplitterWnd::IsTracking and _AFX_* names are Ghidra FID false matches in the statically linked MFC. Never trust them.
  • Whole-function drafts fail on very large functions (17 KB). Chunk by about 110 lines.
  • A builder's own summary of a decode is not evidence: the Tier 2 agent's "about 9300 records per block" claim was wrong and was corrected.
  • gh.sh batch must stop the MCP server first (project lock). It does this itself.
  • Hive streams can hang. Cap with timeout and keep batches resumable.
