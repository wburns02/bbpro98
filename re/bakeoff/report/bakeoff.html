Haiku 5.5 vs GLM-5.3-Flash vs Sonnet 5.5

Each model got the same task text, files, caps and fresh seeds, with no view of the other models' output or the existing winners. Every run was scored by the project's own mechanical referees plus an unseen holdout. All three models passed every tier eventually. What separates them is how many rounds they needed, how well the result generalizes, how good the written spec is, and what each run costs.

Shared failure

Haiku and GLM failed the same holdout game for the same reason. Their replays emit an all-zero batter row (pid 1942, day3 game 2) that the box score omits. Both fitted a narrow drop rule to the two visible days, "players whose only event is caught stealing". The real rule is "drop every all-zero row", and Sonnet wrote it in round 1. The referee and the audit both passed the overfit decoders, and only the unseen day caught it. Each lane saw only "day3 FAIL", the same opaque signal the original run got.

Controls: a toy model that only takes the early exits scores 2327/2500 with 0 deep, and the empty model scores 0.

  • All three are real models. Each was read for oracle tampering and per-record lookups, and none had any.
  • Haiku's model is the most faithful. It takes each action's real frame count from the game's static HHA.DAT table. Sonnet instead assumes the animation is never on its last frame, and documents that.
  • GLM's draft at the 33-minute mark scored 1435/2500 with 0 deep, below the toy control, because it skipped the animation-tick helper. It fixed this within the same round.
  • Read: this task did not separate the models on outcome. One function of about 200 lines, with a strong referee, is within all three. The differences are speed, and how much context each model carries.

Deviations from the plan: st7 has no runner_ai, find_fielder or launch records, so the holdout is the second half of st8. find_fielder was rejected because the per-fielder speed divisor is not in the trace and 485 of 604 records overflow the record buffer. Fielder positioning overflows on every record. Ball launch was too small to separate the models.

Containment and harness notes

  • The Claude lanes ran through a new GLM_BACKEND=claude path in drive.sh: headless claude -p in the same bwrap and pasta jail with the same egress rules, a tmpfs $HOME, and only the credentials file bound read-only. GLM ran on the usual kimi plus Hive path. No Opus, no OpenRouter, no paid Anthropic API.
  • Shared handicap: the referee's systemd-run jail cannot start inside a lane (no user bus). Haiku and GLM each built a local harness around the unchanged referee code. The original GLM run had the same limit.
  • Fixed during the run: the gamebk mask lacked files.json, so the 08:26 launch was aborted and relaunched at 08:33. kimi rejects a file passed as --add-dir, which killed GLM's first tier 3 launch, so drive.sh now passes only directories.
  • The in-pipeline audit returned CLEAN on all 9 runs, including decoders that later failed the holdout and docs with wrong field names. CLEAN means "not cheating", not "semantically right".
